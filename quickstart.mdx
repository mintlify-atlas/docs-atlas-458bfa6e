This guide walks you through sandboxing an application, inspecting running sandboxes, troubleshooting with profiles, and integrating Firejail with your desktop environment.

<Note>
  Make sure Firejail is installed before continuing. See the [installation guide](/installation) if you haven't installed it yet.
</Note>

## Sandbox your first application

<Steps>
  <Step title="Run an application inside a sandbox">
    Prefix any command with `firejail` to run it in a sandbox. Always use the full path to the executable to avoid [firejail-in-firejail issues](https://github.com/netblue30/firejail/issues/2877).

    ```bash
    firejail /usr/bin/firefox
    ```

    Firejail automatically finds and applies the matching security profile from `/etc/firejail/`. You can sandbox any type of application the same way:

    ```bash
    firejail /usr/bin/transmission-gtk   # BitTorrent client
    firejail /usr/bin/vlc                # media player
    firejail /usr/bin/chromium           # Chromium browser
    ```

    For server processes, run with `sudo`:

    ```bash
    sudo firejail /etc/init.d/nginx start
    ```
  </Step>

  <Step title="List running sandboxes">
    In another terminal, run `firejail --list` to see all active sandboxes:

    ```bash
    firejail --list
    ```

    Example output:

    ```console
    $ firejail --list
    1617:netblue:/usr/bin/firejail /usr/bin/firefox-esr
    7719:netblue:/usr/bin/firejail /usr/bin/transmission-qt
    7779:netblue:/usr/bin/firejail /usr/bin/galculator
    7874:netblue:/usr/bin/firejail /usr/bin/vlc
    ```

    Each line shows the PID, the user, and the full command running inside the sandbox.
  </Step>

  <Step title="Verify the installation">
    Confirm Firejail is working and check its version:

    ```bash
    firejail --version
    ```
  </Step>
</Steps>

## Troubleshoot with `--noprofile`

If a sandboxed application fails to start or behaves unexpectedly, disable the security profile to determine whether the profile is the cause:

```bash
firejail --noprofile /usr/bin/firefox
```

If the application works without a profile, the profile is too restrictive for your setup. You can then create a local override at `~/.config/firejail/firefox.local` to relax specific rules without modifying the system-wide profile.

<Tip>
  Local profile overrides in `~/.config/firejail/` are loaded before system profiles. This lets you customize profiles without root access.
</Tip>

## Build a profile for an application

If no profile exists for your application, use `--build` to generate a starting point. Firejail monitors what the application accesses and writes a profile based on that activity:

```bash
firejail --build=myapp.profile /usr/bin/myapp
```

After the session ends, `myapp.profile` contains a generated profile. Review and tighten it before using it in production.

<Warning>
  Auto-generated profiles capture only what the application accessed during that specific session. Test the application thoroughly before treating the profile as complete.
</Warning>

## Integrate with your desktop

Running `firecfg` creates symlinks so that all supported applications automatically launch in a sandbox when started from your desktop, file manager, or application menu — without you needing to type `firejail` each time.

<Steps>
  <Step title="Fix PulseAudio sound (if needed)">
    Run this command to work around shared memory and PID namespace issues in PulseAudio versions prior to 9:

    ```bash
    firecfg --fix-sound
    ```

    Log out and back in for this change to take effect.
  </Step>

  <Step title="Create the desktop integration symlinks">
    ```bash
    sudo firecfg
    ```

    This creates symlinks in `/usr/local/bin` for all applications that Firejail supports. Over 900 applications are covered.
  </Step>

  <Step title="Launch apps normally">
    Start your applications as usual — from your desktop launcher, application menu, or file manager. Firejail runs transparently in the background.

    Verify an application is sandboxed by checking `firejail --list` while it runs.
  </Step>
</Steps>

<Note>
  To see the full list of applications covered by `firecfg`, check `/etc/firejail/firecfg.config` after installation.
</Note>

## Remove desktop integration

If you want to remove the symlinks created by `firecfg` before uninstalling Firejail:

```bash
sudo firecfg --clean
```
